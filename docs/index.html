    Plain-English glossary

    Channel

    One app's private line to the GPU. Each channel has its own queue, so apps do not get in each other's way.

    GPFIFO (the ring of blocks)

    The queue behind a channel: 16 slots in a circle. The app fills slots, the engine empties them, and both keep going round the circle.

    GP_PUT and GP_GET

    Two bookmarks on the ring. PUT is where the app adds the next batch. GET is where the engine reads from next.

    Method / pushbuffer

    A method is one small command (fill memory, copy, signal). A pushbuffer is a list of them. One block on a lane is one pushbuffer.

    Semaphore

    A shared counter used as a signal. One job raises it when done (release). Another job waits until it reaches a value (acquire).

    Timeslice and round-robin

    The engine runs one batch, then moves to the next channel that has work. Taking turns like this keeps it fair.

    Park / context switch

    A channel that must wait for a signal is set aside with its place saved, so the engine can serve others. It resumes exactly where it stopped.

    Watchdog

    A timer that checks how long the engine has been stuck on one batch. Past the limit, it cuts that channel off.

    Fault and recovery

    A channel that hangs or sends a bad command is marked FAULT and its queue is dropped. Other channels are unaffected. Recovery clears it for reuse.

    Acquire timeout

    A limit on how long a channel may wait for a signal. It stops a channel waiting forever for a helper that already crashed.

    Back-pressure (EAGAIN)

    When the ring is full, the app is told "try again later". It slows down instead of piling up work without limit.

    Lock-free ring

    The app and the engine pass work through the ring without ever making each other wait. The app writes first, then moves PUT. The engine reads PUT first, then the data.
